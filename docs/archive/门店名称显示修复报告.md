# 门店名称显示修复报告

## 问题描述

护士长的智能排班页面显示的是门店ID（UUID格式），而不是可读的门店名称，影响用户体验。

**问题截图显示：**
- 当前门店: 1c94c820-114e-4212-9b84-2d923c1014ec

## 问题原因

1. **API层面**：获取单个用户信息的API (`GET /api/profiles/:id`) 只查询了 `profiles` 表，没有关联 `stores` 表获取门店名称
2. **前端类型定义**：`ApiUser` 接口缺少 `store_name` 字段
3. **数据结构**：用户信息中只包含 `store_id`，缺少对应的门店名称

## 修复方案

### 1. 后端API修复

**文件：** `server/api-server.cjs`

**修改内容：**
```javascript
// 修改前：只查询profiles表
const result = await pool.query('SELECT * FROM profiles WHERE id = $1', [id]);

// 修改后：关联查询stores表获取门店名称
const result = await pool.query(
  `SELECT p.id, p.username, p.email, p.full_name, p.role, p.department, p.status,
          p.created_at, p.updated_at, p.dingtalk_userid, p.store_id,
          s.name as store_name
   FROM profiles p
   LEFT JOIN stores s ON p.store_id = s.id
   WHERE p.id = $1`, 
  [id]
);
```

**文件：** `src/services/auth-client.ts`

**修改内容：**


### 3. 前端显示逻辑修复

## 修复效果

### 修复前
- 显示：`当前门店: 1c94c820-114e-4212-9b84-2d923c1014ec`
- 问题：用户无法理解UUID格式的门店标识

### 修复后
- 显示：`当前门店: 默认门店` 或 `当前门店: 上海门店`
- 效果：用户可以清楚地看到自己所属的门店名称

## 技术要点

1. **数据库关联查询**：使用LEFT JOIN确保即使门店信息缺失也不会影响用户信息获取
2. **向后兼容**：保留原有的`store_id`字段，新增`store_name`字段
3. **类型安全**：更新TypeScript类型定义，确保类型检查正确
4. **条件渲染**：使用`store_name`而不是`store_id`作为显示条件，提高用户体验
