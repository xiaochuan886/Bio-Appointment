# 资源可用性检查修复报告

## 问题描述

用户反馈：在预约服务时，系统没有正确屏蔽已被占用的时间段。例如，某个时间段（如15:00-15:30）的房间和护士资源都已被占用，但在创建预约时仍然可以选择该时间段，这是错误的。

## 根本原因

1. **API端点实现过于简单**：`/api/resources/availability` 端点只是简单返回所有状态为 'available' 的资源，完全没有检查时间段冲突。

2. **护士资源缺失**：数据库 `resources` 表中没有护士资源记录，导致查询不到任何护士。

3. **数据模型理解错误**：
   - `schedules.nurse_id` 关联的是 `profiles` 表（用户表），不是 `resources` 表
   - `schedules.room_id` 关联的是 `resources` 表
   - 护士和房间使用不同的数据源

## 修复方案

### 1. 修复资源可用性API端点 (server/api-server.cjs)

**修改前**：
```javascript
// 简单返回所有可用资源，不检查时间冲突
const result = await pool.query(
  `SELECT * FROM resources WHERE status = 'available' ORDER BY name`
);
```

**修改后**：
```javascript
// 查询房间：排除在指定时间段有排班的房间
let roomQuery = `
  SELECT r.* 
  FROM resources r
  WHERE r.type IN ('room', 'vip', 'treatment', 'consultation')
    AND r.status = 'available'
    ${store_id ? 'AND r.store_id = $4' : ''}
    AND NOT EXISTS (
      SELECT 1 FROM schedules s
      WHERE s.room_id = r.id
        AND s.scheduled_date = $1
        AND s.status != 'cancelled'
        AND (s.scheduled_time_start, s.scheduled_time_end) OVERLAPS ($2::time, $3::time)
    )
  ORDER BY r.name
`;

// 查询护士：从profiles表查询，排除在指定时间段有排班的护士
let nurseQuery = `
  SELECT p.id, p.full_name as name, p.role as type, p.store_id
  FROM profiles p
  WHERE p.role IN ('nurse', 'head_nurse')
    AND p.status = 'active'
    ${store_id ? 'AND p.store_id = $4' : ''}
    AND NOT EXISTS (
      SELECT 1 FROM schedules s
      WHERE s.nurse_id = p.id
        AND s.scheduled_date = $1
        AND s.status != 'cancelled'
        AND (s.scheduled_time_start, s.scheduled_time_end) OVERLAPS ($2::time, $3::time)
    )
  ORDER BY p.full_name
`;
```

**关键改进**：
- 使用 `OVERLAPS` 操作符检查时间段冲突
- 排除已取消的排班 (`status != 'cancelled'`)
- 支持门店筛选
- 返回 `has_available_room` 和 `has_available_nurse` 标志

### 2. 更新前端检查逻辑 (src/pages/sales/AppointmentPage.tsx)

**修改后**：

## 数据模型说明

### 关键表结构
```
profiles (用户表)
├── id
├── full_name
├── role (nurse, head_nurse, doctor, sales, etc.)
└── store_id

resources (资源表)
├── id
├── name
├── type (room, vip, treatment, consultation, nurse)
└── store_id

schedules (排班表)
├── id
├── appointment_id
├── scheduled_date
├── scheduled_time_start
├── scheduled_time_end
├── room_id → resources.id
├── nurse_id → profiles.id  ← 注意：关联到profiles，不是resources
└── status
```

### 重要发现
- **护士资源**：`schedules.nurse_id` 直接关联 `profiles` 表，不需要通过 `resources` 表
- **房间资源**：`schedules.room_id` 关联 `resources` 表
- **时间冲突检测**：使用 PostgreSQL 的 `OVERLAPS` 操作符
