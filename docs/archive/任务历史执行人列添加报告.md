# 任务历史执行人列添加报告

## 功能概述

为任务历史页面的表格添加了"执行人"列，显示被分配执行任务的护士或护士长信息，提升数据的完整性和可读性。

## 实现内容

### 1. 表格结构优化 (`src/pages/nurse/HistoryPage.tsx`)

**修改前的表格列：**
```
日期 | 客户 | 服务项目 | 房间 | 门店 | 时间 | 状态 | 操作
```

**修改后的表格列：**
```
日期 | 客户 | 服务项目 | 房间 | 门店 | 执行人 | 时间 | 状态 | 操作
```

### 2. 执行人数据显示

**数据来源：**
- 优先显示：`task.nurse?.name` (护士对象中的姓名)
- 备选显示：`task.nurse_name` (API直接返回的护士姓名)
- 降级显示：`护士 #${task.nurse_id.substring(0, 8)}` (护士ID简写)
- 默认显示：`未分配` (无护士分配时)

**实现代码：**
```tsx
<TableCell className="font-medium">
  {task.nurse?.name || task.nurse_name || (task.nurse_id ? `护士 #${task.nurse_id.substring(0, 8)}` : '未分配')}
</TableCell>
```

### 3. CSV导出功能增强

**导出表头更新：**
```javascript
const headers = [
  '日期', '客户姓名', '服务项目', '房间', '门店', '执行人',
  '开始时间', '结束时间', '状态', '实际时长(分钟)', '超时(分钟)'
];
```

**导出数据包含执行人：**
```javascript
const csvData = filteredTasks.map(task => [

  task.fullAppointment?.service?.name || '未知服务',
  task.room?.name || '未分配房间',
  task.appointment?.store?.name || task.fullAppointment?.store?.name || '',
  task.nurse?.name || task.nurse_name || '未分配', // 新增执行人信息
  // ... 其他字段

```

## 数据支持

### 服务端API支持

服务端 `/api/schedules` 接口已经包含完整的护士信息查询：

```sql
SELECT
  s.*,
  -- ... 其他字段
  p.full_name as nurse_name,
  p.role as nurse_role,
  p.department as nurse_department
FROM schedules s
LEFT JOIN profiles p ON s.nurse_id = p.id
-- ... 其他JOIN
```

### 数据转换

服务端返回的数据结构包含：
```javascript
{
  // ... 其他字段
  nurse_name: "张护士",
  nurse_role: "nurse",
  nurse_department: "护理部",
  nurse: {
    id: "nurse-id",
    name: "张护士",
    role: "nurse",
    department: "护理部"
  }
}
```

## 显示逻辑

### 执行人显示优先级
1. **护士姓名**：`task.nurse?.name` 或 `task.nurse_name`
2. **护士ID简写**：`护士 #12345678` (当有ID但无姓名时)
3. **未分配状态**：`未分配` (当无护士分配时)

### 不同角色的显示效果
- **护士角色**：显示护士姓名，如"张护士"
- **护士长角色**：显示护士长姓名，如"李护士长"
- **未分配任务**：显示"未分配"
- **数据缺失**：显示护士ID简写作为降级方案
