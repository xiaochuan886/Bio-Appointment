# 医生门店隔离问题修复报告

## 问题描述

用户报告：销售发起了一个医生咨询的预约，选的是上海门店，但上海门店和默认门店的医生都能看到这个预约，且预约信息的门店都是当前医生的门店。

## 问题分析

经过详细调查，发现了以下问题：

### 1. 根本原因
- **数据不一致**：部分医生账户的 `store_id` 字段为 `NULL`
- **安全漏洞**：后端API没有对无门店ID的医生进行严格验证

### 2. 实际情况
通过测试发现：
- ✅ **门店隔离机制本身是正常工作的**
- ✅ 有正确门店ID的医生只能看到自己门店的预约
- ❌ 部分医生账户缺少门店ID配置
- ❌ 后端对无门店医生的处理不够安全

## 修复措施

### 1. 后端API安全加固

**文件**: `server/api-server.cjs`
**位置**: `/api/appointments/doctor-pending` 端点

```javascript
// 添加安全检查：医生必须有门店ID
if (userProfile.role === 'doctor') {

    return res.status(403).json({
      error: 'Access denied',
      message: '医生账户未分配门店，请联系管理员配置门店信息'
    });
  }
  // ... 其他逻辑
}
```

**执行脚本**: `fix-doctor-store-assignments.cjs`

- ✅ `doctor_default_test` → 默认门店
- ✅ 所有医生账户现在都有正确的门店分配

```sql

ADD CONSTRAINT check_doctor_has_store
```
