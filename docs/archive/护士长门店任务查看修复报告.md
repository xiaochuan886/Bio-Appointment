# 护士长门店任务查看修复报告

## 问题描述

护士长在任务历史页面选择"门店任务"时，只能看到2个任务（自己的），而不是门店的所有3个任务。这与周视图显示的排班数量不一致。

## 问题分析

### 根本原因
1. **服务端API限制**：`/api/schedules` 接口只允许管理员按 `store_id` 筛选，护士长无法使用此参数
2. **前端筛选逻辑不完整**：前端筛选时没有正确处理排班门店ID和预约门店ID的关系
3. **数据一致性问题**：排班记录的 `store_id` 可能为空或与预约的 `store_id` 不一致

### 具体问题
- 服务端代码：`if (store_id && userProfile.role === 'super_admin')` 只允许管理员筛选
- 前端逻辑：护士长选择门店任务时，API筛选失效，导致数据不完整
- 数据结构：需要同时检查 `schedule.store_id` 和 `appointment.store_id`

## 修复方案

### 1. 服务端API修复 (`server/api-server.cjs`)

**修复前：**
```javascript
// 只有管理员可以按门店ID筛选
if (store_id && userProfile.role === 'super_admin') {
```

**修复后：**
```javascript
// 管理员和护士长可以按门店ID筛选
if (store_id && (userProfile.role === 'super_admin' || userProfile.role === 'head_nurse')) {
  // 护士长只能筛选自己的门店
  if (userProfile.role === 'head_nurse' && store_id !== userProfile.store_id) {
    return res.status(403).json({
      error: 'Access denied',
      message: '护士长只能查看自己门店的数据'
    });
  }
```

### 2. 前端筛选逻辑优化 (`src/pages/nurse/HistoryPage.tsx`)

**修复前：**
```typescript
return schedule.store_id === user.profile?.store_id || 
       schedule.appointment?.store_id === user.profile?.store_id;
```

**修复后：**
```typescript
// 门店任务：检查排班门店ID或预约门店ID是否匹配
const userStoreId = user.profile?.store_id;
const scheduleStoreId = schedule.store_id;
const appointmentStoreId = schedule.appointment?.store_id || schedule.fullAppointment?.store_id;

return userStoreId && (
  scheduleStoreId === userStoreId || 
  appointmentStoreId === userStoreId
);
```

### 3. API调用策略调整

**修复前：**
```typescript
const filters = getTaskHistoryFilters(userProfile, dataScope);
Object.assign(params, filters);
```

**修复后：**
```typescript
if (canViewAllData) {
  // 管理员不设置筛选条件
} else if (canChooseScope && dataScope === 'store') {
  // 护士长查看门店任务时，不在API层筛选，而是获取更多数据在前端筛选
  // 这样可以确保包含所有可能相关的任务
} else {
  // 其他情况使用标准筛选
  const filters = getTaskHistoryFilters(userProfile, dataScope);
  Object.assign(params, filters);
}
```

## 修复效果

### 权限控制矩阵

| 用户角色 | 个人任务 | 门店任务 | 其他门店任务 | API支持 |
|---------|---------|---------|-------------|---------|
| 管理员 | ✅ | ✅ | ✅ | ✅ |
| 护士长 | ✅ | ✅ | ❌ | ✅ |
| 护士 | ✅ | ❌ | ❌ | ✅ |

### 数据访问流程

1. **护士长选择"我的任务"**
   - API筛选：`nurse_id = head_nurse_id`
   - 前端验证：确认任务分配给护士长本人
   - 结果：只显示护士长自己的任务

2. **护士长选择"门店任务"**
   - API筛选：`store_id = head_nurse_store_id`
   - 前端验证：检查排班门店ID或预约门店ID匹配
   - 结果：显示门店内所有护士的任务

3. **安全控制**
   - 护士长无法访问其他门店的数据
   - API层面进行权限验证
   - 前端进行二次数据验证
