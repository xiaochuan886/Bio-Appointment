# 🔧 钉钉同步只同步12人的问题修复

## 🔍 问题分析

### 原始问题
- **实际情况**：钉钉组织中有 30+ 人
- **同步结果**：只同步了 12 人
- **组织结构**：有多级部门嵌套

### 根本原因

**代码只获取了一级子部门，没有递归获取所有嵌套部门**

原始代码：
```javascript
// ❌ 问题代码：只获取 dept_id=1 的直接子部门
const deptResponse = await fetch(
  `https://oapi.dingtalk.com/topapi/v2/department/listsub?access_token=${accessToken}`,
  {
    method: 'POST',
    body: JSON.stringify({ dept_id: 1 })  // 只获取根部门的直接子部门
  }
);
```

**影响**：
- 只同步了第一层部门的用户
- 如果用户在子部门的子部门中，就不会被同步

根据您的组织架构图：
```
山丘生物（杭州）有限公司 (根部门)
├── 管理部 (1人)
├── 财务部 (2人)
├── 人事行政部 (2人)
├── 市场系统部 (1人)
├── 线上运营 (1人)
├── 技术部 (12人) ← 只同步了这个部门
├── 山丘杭州 (12人)
├── 山丘上海 (6人)
└── 山丘北戴河 (1人)
```

如果"技术部"里有12个用户，而其他部门可能是嵌套的或者有特殊情况，导致只同步了12人。

---

## ✅ 修复方案

### 1. **递归获取所有部门**

新增递归函数，获取所有层级的部门：

```javascript
// ✅ 修复后：递归获取所有部门
const getAllDepartments = async (parentDeptId = 1) => {
  // 获取当前部门的子部门
  const response = await fetch(
    `https://oapi.dingtalk.com/topapi/v2/department/listsub?access_token=${accessToken}`,
    {
      method: 'POST',
      body: JSON.stringify({ dept_id: parentDeptId })
    }
  );
  const data = await response.json();
  
  if (data.errcode !== 0 || !data.result) {
    return [];
  }
  
  let allDepts = data.result || [];
  
  // 递归获取每个子部门的子部门
  for (const dept of data.result) {
    const subDepts = await getAllDepartments(dept.dept_id);
    allDepts = allDepts.concat(subDepts);
  }
  
  return allDepts;
};

const allDepartments = await getAllDepartments(1);
console.log(`Found ${allDepartments.length} departments (including all levels)`);
```

## ⚠️ 可能的其他问题

### 问题1：部门用户数量限制

**钉钉API限制**：每次请求最多返回 100 个用户

**解决方案**：代码已经使用分页机制（`cursor` + `has_more`），会自动处理大部门

```javascript
while (hasMore) {
  // 每次请求100个用户
  body: JSON.stringify({
    dept_id: parseInt(deptId),
    cursor,
    size: 100  // 每页100个
  })
  // ...
  hasMore = userData.result.has_more;
  cursor = userData.result.next_cursor;
}
```

### 问题2：用户重复（一人多部门）

**现象**：如果一个用户同时在多个部门，可能被计数多次

**解决方案**：使用 `username`（钉钉的 `userid`）作为唯一标识，数据库中自动去重

```javascript
// 检查用户是否存在
const existingUser = await pool.query(
  'SELECT id FROM profiles WHERE username = $1',
  [user.userid]  // 使用钉钉的userid作为唯一标识
);

if (existingUser.rows.length > 0) {
  // 用户已存在，根据策略更新或跳过
} else {
  // 创建新用户
}
```

### 问题3：API权限不足

**现象**：某些部门获取失败

**检查**：
1. 查看日志是否有 "Failed to fetch users" 错误

3. 确认应用已分配给所有需要同步的部门
