## 简介
Bio-Appointment系统的注册接口允许新用户创建账户。该接口通过POST /api/auth/register端点实现，处理用户注册请求，验证用户名唯一性，对密码进行哈希处理，并为新用户分配默认角色。本文档详细描述了注册接口的实现，包括HTTP方法、请求参数、请求体结构和响应格式。

## 注册接口详情
注册接口通过POST方法暴露在/api/auth/register端点上。它接受包含用户名、密码、全名和邮箱的JSON请求体，并返回包含新创建用户信息的响应。

### HTTP方法
`POST`

### 请求URL
`/api/auth/register`

### 请求头
```json
{
  "Content-Type": "application/json"
}
```

### 请求参数
| 参数 | 类型 | 必需 | 描述 |
|------|------|------|------|
| username | string | 是 | 用户名，用于登录 |
| password | string | 是 | 用户密码 |
| full_name | string | 否 | 用户真实姓名 |
| email | string | 否 | 用户邮箱 |

### 请求体结构
```json
{
  "username": "string",
  "password": "string",
  "full_name": "string",
  "email": "string"
}
```

### 响应格式
成功注册时，服务器返回200状态码和包含新用户信息的JSON响应：
```json
{
  "user": {
    "id": "string",
    "username": "string",
    "email": "string",
    "full_name": "string",
    "role": "string",
    "department": "string",
    "status": "string",
    "created_at": "string",
    "updated_at": "string"
  }
}
```

## 业务逻辑分析
AuthService.register方法实现了注册接口的核心业务逻辑。该方法首先检查用户名是否已存在，然后对密码进行哈希处理，创建新用户，并分配默认角色。

### 用户名唯一性检查
在创建新用户之前，系统会检查用户名是否已存在。如果用户名已存在，将抛出错误。

```javascript
const existingUser = await connection_1.DatabaseHelper.findMany('profiles', { username });
if (existingUser.length > 0) {
    throw new Error('Username already exists');
}
```

### 密码哈希处理
系统使用bcrypt库对用户密码进行哈希处理，saltRounds设置为12，以确保密码安全。

```javascript
static async hashPassword(password) {
    const saltRounds = 12;
    return await bcrypt_1.default.hash(password, saltRounds);
}
```

### 默认角色分配
新注册的用户被分配默认角色'sales'。第一个注册的用户将自动成为超级管理员。

```javascript
const newUser = await connection_1.DatabaseHelper.create('profiles', {
    username,
    email: credentials.email,
    full_name,
    password_hash: passwordHash,
    role: 'sales', // Default role
    status: 'active',
});
```

### 用户创建流程
1. 验证请求参数
2. 检查用户名唯一性
3. 哈希密码
4. 创建用户记录
5. 返回用户信息（不含密码哈希）

## 前端调用示例
前端通过auth-client.ts中的ClientAuthService.register方法调用注册接口。以下是如何在前端代码中使用此接口的示例：

```typescript
import { ClientAuthService } from '@/services/auth-client';

async function handleRegister() {
  try {
    const user = await ClientAuthService.register({
      username: 'newuser',
      password: 'securepassword',
      full_name: 'New User',
      email: 'newuser@example.com'
    });
    console.log('注册成功:', user);
  } catch (error) {
    console.error('注册失败:', error.message);
  }
}
```

### 处理注册成功
当注册成功时，前端通常会显示成功消息，并重定向用户到登录页面。

```typescript
const onSubmit = async (values: RegisterFormValues) => {
  try {
    const result = await register({
      username: values.username,
      password: values.password,
      full_name: values.full_name,
    });
    toast.success('注册成功！请登录');
    navigate('/login');
  } catch (error: any) {
    // 处理错误
  }
};
```

### 处理用户名已存在
当用户名已存在时，后端返回错误，前端应显示相应的错误消息。

```typescript
catch (error: any) {
  let errorMessage = '注册失败，请稍后重试';

    errorMessage = '该用户名已被注册';
```

## 安全要求
为了确保生产环境中的安全性，注册接口实施了多项安全措施。

### 密码强度验证
前端在提交前对密码进行强度验证，确保密码至少6个字符。

```typescript
const registerSchema = z.object({
  password: z.string()
    .min(6, '密码至少6个字符')
    .max(50, '密码最多50个字符'),
});
```

### 邮箱确认机制
系统通过触发器自动处理邮箱确认，第一个注册的用户自动成为超级管理员，后续用户默认角色为sales。

```sql
CREATE OR REPLACE FUNCTION handle_new_user()
RETURNS trigger
LANGUAGE plpgsql
SECURITY DEFINER SET search_path = public
AS $$
DECLARE
  user_count int;
  extracted_username text;
BEGIN
  SELECT COUNT(*) INTO user_count FROM profiles;
  
  extracted_username := SPLIT_PART(NEW.email, '@', 1);
  
  INSERT INTO profiles (id, username, email, role)
  VALUES (
    NEW.id,
    extracted_username,
    NEW.email,
    CASE 
      WHEN user_count = 0 THEN 'super_admin'::user_role 
      ELSE 'sales'::user_role 
    END
  );
  
  RETURN NEW;
END;
$$;
```

## 数据库设计
注册接口依赖于profiles表来存储用户信息。该表设计合理，包含了用户的基本信息和安全相关的字段。

### profiles表结构
| 字段 | 类型 | 描述 |
|------|------|------|
| id | UUID | 用户唯一标识符 |
| username | VARCHAR(255) | 用户名，唯一且不为空 |
| email | VARCHAR(255) | 邮箱 |
| full_name | VARCHAR(255) | 真实姓名 |
| role | user_role | 用户角色，默认为'sales' |
| department | VARCHAR(255) | 所属部门 |
| status | user_status | 用户状态，默认为'active' |
| password_hash | VARCHAR(255) | 密码哈希值 |
| created_at | TIMESTAMP | 创建时间 |
| updated_at | TIMESTAMP | 更新时间 |

### 枚举类型
系统定义了user_role和user_status枚举类型，以确保数据的一致性和完整性。

```sql
CREATE TYPE user_role AS ENUM ('super_admin', 'sales', 'head_nurse', 'nurse', 'doctor');
CREATE TYPE user_status AS ENUM ('active', 'disabled');
```
