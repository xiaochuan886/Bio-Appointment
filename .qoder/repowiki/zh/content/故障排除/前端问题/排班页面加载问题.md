## 问题描述

智能排班页面存在数据加载失败的问题，导致护士长无法查看待排班预约和已有排班记录。该问题是由于Supabase查询中JOIN语法错误导致的数据查询失败。

**影响范围**：
- 护士长端 - 智能排班看板页面
- 所有涉及预约和排班数据查询的功能

**严重程度**：高（核心功能无法使用）

**具体现象**：
- 智能排班页面提示"加载数据失败"
- 无法查看待排班的预约
- 无法查看已有的排班记录
- 预约列表、排班列表、甘特图等核心功能无法正常显示

## 根本原因分析

### 根本原因

在Supabase的查询中，JOIN关联表的语法错误导致查询失败。当多个外键指向同一个表时，必须使用外键约束名来区分，否则Supabase无法正确解析查询。

**错误的JOIN语法**：
```typescript
// ❌ 错误：使用字段名作为表名
sales:sales_id(id, name, role)
doctor:doctor_id(id, name, role)
room:room_id(id, name, type, category)
nurse:nurse_id(id, name, type)
```

**正确的JOIN语法**：
```typescript
// ✅ 正确：使用外键约束名指定关联
sales:profiles!appointments_sales_id_fkey(id, name, role)
doctor:profiles!appointments_doctor_id_fkey(id, name, role)
room:rooms(id, name, room_type)
nurse:nurses(id, name, skill_level)
```

### 涉及的函数

1. **getAppointments()** - 获取预约列表
2. **getAppointmentById()** - 获取单个预约详情
3. **getSchedules()** - 获取排班列表
4. **getScheduleById()** - 获取单个排班详情

### 技术细节

**Supabase外键关联规则**：
- 当多个外键指向同一个表时，必须使用外键约束名来区分
- 格式：`alias:table_name!foreign_key_constraint_name(columns)`
- 例如：`sales:profiles!appointments_sales_id_fkey(id, name, role)`

**外键约束名查询**：
```sql
SELECT 
  conname AS constraint_name,
  a.attname AS column_name,
  confrelid::regclass AS foreign_table_name
FROM pg_constraint c
JOIN pg_attribute a ON a.attnum = ANY(c.conkey) AND a.attrelid = c.conrelid
WHERE conrelid = 'appointments'::regclass
AND contype = 'f';
```

## 技术细节

### 外键约束问题

在数据库设计中，当多个外键指向同一个表时，必须使用外键约束名来区分。在本项目中，`appointments`表的`sales_id`和`doctor_id`都指向`profiles`表，因此需要使用不同的外键约束名来区分。

```sql
-- 查看appointments表的外键约束
SELECT 
  conname AS constraint_name,
  a.attname AS column_name,
  confrelid::regclass AS foreign_table_name
FROM pg_constraint c
JOIN pg_attribute a ON a.attnum = ANY(c.conkey) AND a.attrelid = c.conrelid
WHERE conrelid = 'appointments'::regclass
AND contype = 'f';
```

查询结果：
- `appointments_sales_id_fkey` -> profiles
- `appointments_doctor_id_fkey` -> profiles
- `appointments_service_id_fkey` -> services

### 数据库表结构

**appointments表**：
- `sales_id` → profiles (外键约束名: appointments_sales_id_fkey)
- `doctor_id` → profiles (外键约束名: appointments_doctor_id_fkey)
- `service_id` → services (外键约束名: appointments_service_id_fkey)

**schedules表**：
- `appointment_id` → appointments (外键约束名: schedules_appointment_id_fkey)
- `room_id` → rooms (外键约束名: schedules_room_id_fkey)
- `nurse_id` → nurses (外键约束名: schedules_nurse_id_fkey)
- `created_by` → profiles (外键约束名: schedules_created_by_fkey)

### 外键约束修复

在`00003_fix_schedules_foreign_keys.sql`迁移文件中，修复了schedules表的外键约束：

```sql
-- 删除旧的外键约束（指向resources表）
ALTER TABLE schedules 
DROP CONSTRAINT IF EXISTS schedules_room_id_fkey;

ALTER TABLE schedules 
DROP CONSTRAINT IF EXISTS schedules_nurse_id_fkey;

-- 添加新的外键约束（指向rooms和nurses表）
ALTER TABLE schedules 
ADD CONSTRAINT schedules_room_id_fkey 
FOREIGN KEY (room_id) 
REFERENCES rooms(id) 
ON DELETE RESTRICT;

ALTER TABLE schedules 
ADD CONSTRAINT schedules_nurse_id_fkey 
FOREIGN KEY (nurse_id) 
REFERENCES nurses(id) 
ON DELETE RESTRICT;
```

## 错误处理改进

### 改进loadData函数的错误处理

**文件**：`src/pages/head-nurse/SchedulePage.tsx`

**修改前**：
```typescript
const loadData = async () => {
  try {
    // ... 加载数据
  } catch (error) {
    toast.error('加载数据失败');
  }
};
```

**修改后**：
```typescript
const loadData = async () => {
  try {
    // ... 加载数据
  } catch (error) {
    console.error('加载数据失败:', error);
    const errorMessage = error instanceof Error ? error.message : '未知错误';
    toast.error(`加载数据失败: ${errorMessage}`);
  }
};
```

**改进点**：
- 添加console.error输出，便于调试
- 显示具体的错误信息，而不是通用的"加载数据失败"
- 帮助快速定位问题

### 错误处理最佳实践

## 最佳实践

### Supabase JOIN语法规则

1. **单一外键关联**
   ```typescript
   // 当外键唯一指向某个表时，可以直接使用表名
   service:services(*)
   ```

2. **多个外键指向同一表**
   ```typescript
   // 必须使用外键约束名来区分
   sales:profiles!appointments_sales_id_fkey(id, name, role)
   doctor:profiles!appointments_doctor_id_fkey(id, name, role)
   ```

3. **嵌套关联**
   ```typescript
   // 可以在关联的表中继续关联其他表
   appointment:appointments(
     *,
     service:services(*),
     sales:profiles!appointments_sales_id_fkey(id, name, role)
   )
   ```
