## 简介

本指南旨在帮助新开发者在本地环境中成功搭建和运行 Bio-Appointment 智能预约调度系统。文档涵盖了从环境准备、依赖安装、环境变量配置、数据库初始化到服务启动的完整流程。通过详细的命令行指令和预期输出结果，确保零基础用户也能顺利完成系统部署。同时为有经验的开发者提供快速配置路径，并针对常见初始化问题提供排查建议。

## 环境准备

在开始部署 Bio-Appointment 系统之前，需要确保本地开发环境满足以下要求。系统依赖 Node.js 运行时、包管理工具 pnpm、Docker 容器平台以及 PostgreSQL 数据库服务。

### Node.js 和 pnpm 安装

Bio-Appointment 系统要求 Node.js 版本不低于 20，建议使用最新稳定版本以获得最佳兼容性和性能。

```bash
# 检查 Node.js 版本
node -v
# 预期输出: v20.x.x 或更高版本

# 检查 npm 版本
npm -v
# 预期输出: 10.x.x 或更高版本
```

推荐使用 pnpm 作为包管理工具，它比 npm 更快且更节省磁盘空间：

```bash
# 全局安装 pnpm
npm install -g pnpm

# 验证 pnpm 安装
pnpm -v
# 预期输出: 9.x.x 或更高版本
```

### Docker 安装

系统使用 Docker Compose 来管理数据库服务（PostgreSQL 和 Redis），因此需要安装 Docker Desktop 或 Docker Engine。

```bash
# 检查 Docker 安装
docker --version
# 预期输出: Docker version 20.x.x, build xxxxxxx

# 检查 Docker Compose 安装
docker-compose --version
# 预期输出: docker-compose version 2.x.x, build xxxxxxx
```

### PostgreSQL 依赖

虽然系统通过 Docker 运行 PostgreSQL 服务，但了解其配置有助于问题排查。数据库服务配置在 `docker-compose.yml` 文件中，使用 PostgreSQL 15 镜像，映射本地端口 5437 到容器端口 5432。

## 环境变量配置

环境变量是系统正常运行的关键，它们定义了数据库连接、JWT 密钥等重要配置。

### 复制环境变量模板

项目提供了 `.env.example` 作为模板文件，需要将其复制为 `.env.local` 并根据需要进行修改：

```bash
# 复制环境变量模板
cp .env.example .env.local
```

### 配置关键环境变量

打开 `.env.local` 文件，主要需要配置以下几项：

```env
# 数据库类型：local（本地）或 supabase（遗留）
DATABASE_TYPE=local

# 本地数据库配置
POSTGRES_HOST=localhost
POSTGRES_PORT=5437
POSTGRES_DB=bio_appointment
POSTGRES_USER=app_user
POSTGRES_PASSWORD=secure_password_123

# JWT 配置
JWT_SECRET=your-super-secret-jwt-key-change-in-production

# 应用配置
VITE_APP_URL=http://localhost:5173
VITE_API_BASE_URL=http://localhost:5173/api
```

## 数据库初始化

数据库初始化是系统部署的核心步骤，包括启动数据库服务和执行初始化脚本。

### 使用 Docker 启动数据库服务

系统通过 `docker-compose.yml` 文件定义了 PostgreSQL 和 Redis 服务：

```bash
# 启动数据库服务（后台运行）
docker-compose up -d postgres redis

# 查看服务状态
docker-compose ps
# 预期输出包含 bio-appointment-postgres 和 bio-appointment-redis 且状态为 Up
```

### 执行数据库初始化脚本

使用提供的 `migrate.sh` 脚本进行数据库初始化：

```bash
# 初始化数据库
./database/migrate.sh init

# 检查数据库状态
./database/migrate.sh status
```

初始化过程会执行 `database/init/` 目录下的 SQL 脚本，按顺序创建数据库结构和初始数据。

## 服务启动与验证

完成数据库初始化后，即可启动前后端服务并验证系统健康状态。

### 使用启动脚本一键部署

项目提供了 `start.sh` 脚本，可一键完成环境检查、依赖安装、数据库启动和应用启动：

```bash
# 赋予脚本执行权限
chmod +x start.sh

# 执行一键启动
./start.sh

# 或指定仅启动数据库
./start.sh database-only

# 查看系统状态
./start.sh status
```

### 手动启动前后端服务

也可以分步手动启动服务：

```bash
# 1. 启动 API 服务器（后台运行）
nohup node server/api-server.cjs > /tmp/api-server.log 2>&1 &

# 2. 启动前端开发服务器
npm run dev -- --host 127.0.0.1
```

### 验证服务健康状态

通过访问健康检查端点来验证服务是否正常运行：

```bash
# 检查 API 服务器健康状态
curl http://localhost:3001/api/health

# 预期输出:
# {
#   "status": "healthy",
#   "database": {
#     "status": "connected",
#     "timestamp": "2024-01-01T00:00:00.000Z"
#   },
#   "timestamp": "2024-01-01T00:00:00.000Z"
# }
```

前端服务默认在 `http://localhost:5173` 启动。

## Docker 部署

系统支持通过 Docker Compose 进行容器化部署，适用于开发和生产环境。

```bash
# 开发环境启动
docker-compose up -d

# 生产环境构建和启动
docker-compose -f docker-compose.prod.yml build
docker-compose -f docker-compose.prod.yml up -d

# 停止所有服务
docker-compose down
```

`docker-compose.yml` 文件定义了三个服务：`postgres`、`redis` 和可选的 `pgadmin`（用于数据库管理）。

## 常见问题排查

在系统初始化过程中，可能会遇到一些常见问题，以下是排查建议。

### 数据库连接失败

**症状**：`docker exec bio-appointment-postgres pg_isready` 命令返回连接失败。

**解决方案**：
1. 确认 Docker 服务已启动
2. 检查 `docker-compose.yml` 中的端口映射是否正确
3. 验证环境变量中的数据库密码是否与 `docker-compose.yml` 一致
4. 查看数据库容器日志：`docker logs bio-appointment-postgres`

### 环境变量缺失或错误

**症状**：应用启动时报错，提示无法连接数据库或 JWT 验证失败。

**解决方案**：
1. 确认已创建 `.env.local` 文件
2. 检查 `.env.local` 文件中的变量名是否正确
3. 验证 `POSTGRES_PASSWORD` 在 `.env.local` 和 `docker-compose.yml` 中是否一致
4. 重启应用以加载新的环境变量

### 端口占用问题

**症状**：启动服务时提示端口已被占用。

**解决方案**：
1. 检查端口占用情况：
   ```bash
   lsof -i :5173  # 前端开发服务器
   lsof -i :3001  # API 服务器
   lsof -i :5437  # PostgreSQL
   ```
2. 终止占用端口的进程或修改服务配置使用其他端口

## 附录

### 数据库初始化脚本说明

| 脚本文件 | 功能描述 |
|---------|---------|
| `01-init-database.sql` | 创建数据库扩展、自定义枚举类型、审计日志表和权限 |
| `02-create-tables.sql` | 创建核心业务表（用户、预约、排班、资源等）和索引 |
| `03-seed-data.sql` | 插入初始数据（服务、资源、用户、部门等） |
| `04-dingtalk-sync-tables.sql` | 创建钉钉同步相关的配置和日志表 |

### 启动脚本命令说明

`start.sh` 脚本支持以下命令：

- `start`：完整启动（默认）
- `database-only`：仅启动数据库
- `init-only`：仅初始化数据库
- `install-only`：仅安装依赖
- `status`：查看系统状态
- `stop`：停止所有服务
- `clean`：清理所有数据和容器
- `help`：显示帮助信息
